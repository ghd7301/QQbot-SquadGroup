# 消息判断与队列链路

本文记录当前已部署版本的消息判断与队列行为。图中描述的是现状，不包含尚未实施的 P0-P3 两阶段调度方案。

## 消息判断链路

语义规划先决定消息进入知识问答、闲聊、Bot 内部信息或身份回复分支；只有知识意图和明确对 Bot 消息的安全降级才执行知识库检索。明确对 Bot 的消息和普通消息分别统计规划故障，互不触发对方的熔断。

```mermaid
flowchart TD
    A["QQ群消息"] --> B["硬关系检查：群、@、引用、发送者"]
    B --> C["分段合并并进入持久队列"]
    C --> D["读取近期上下文、追问关系、记忆候选"]
    D --> F{"语义规划是否可用"}
    F -->|可用| G{"受话人、意图、参与关系"}
    F -->|不可用且明确对 Bot 说| E["检索候选知识用于安全降级"]
    F -->|不可用且未对 Bot 说| M["不回复"]
    E --> I["受保护 fallback"]
    G -->|knowledge| H["检索知识并检查命中强度"]
    G -->|闲聊/调侃/批评等| I["闲聊或被@ fallback"]
    G -->|bot_meta| J["能力复核 + 管理员鉴权"]
    G -->|control_attempt| U["本地固定操作边界"]
    G -->|identity| K["固定身份回复"]
    H -->|强命中| L["知识库回答"]
    H -->|弱命中且明确对 Bot 说| I
    H -->|弱命中且未对 Bot 说| M["不回复"]
    I --> N["生成回复"]
    J --> N
    K --> N
    L --> N
    U --> P
    N --> O{"是否需要模型终审"}
    O -->|无风险且无相关新消息| P["本地事实与安全校验"]
    O -->|弱知识、风险或相关新消息| Q["模型终审"]
    Q -->|通过或安全修订| P
    Q -->|不可用或低置信| R{"是否有确定性安全降级"}
    R -->|有| P
    R -->|没有| M
    P --> S["晚消息硬关系复核"]
    S --> T["限流、发送锁、OneBot 确认、审计"]
```

终审故障时，强知识答案只有在没有相关上下文变化、没有风险标记且精确事实可由知识片段支持时才可继续发送；弱知识问题返回保守的资料不足答复，其余情况保持不回复。控制请求在生成前已经转为本地固定边界，不依赖生成或终审模型。

普通消息规划连续失败 5 次后暂停 30 秒；冷却结束时只允许一个半开探测请求，探测成功立即恢复，失败则重新冷却。明确对 Bot 的消息不受普通消息熔断影响。
健康接口分别暴露两条线路自进程启动以来的尝试数、不可用数、可用率、连续失败数、熔断状态和半开探测状态。

## 当前队列与软抢占

当前使用两条独立入口处理通道。本轮可靠性优化没有调整该队列结构。排队中的普通消息会为 @/回复 Bot 的消息让路；已经开始的普通模型请求不会被强制中断。

```mermaid
flowchart LR
    A["消息进入"] --> B["分段聚合"]
    B --> C{"是否 @ / 回复 Bot"}
    C -->|是| D["优先队列 priority=0"]
    C -->|否| E["普通队列 priority=1"]
    D --> F["优先 Worker"]
    E --> G["普通 Worker"]
    G --> H{"优先队列有消息？"}
    H -->|有| I["普通消息重新入队，等待 50ms"]
    H -->|没有| J["开始规划和生成"]
    F --> K["立即开始规划和生成"]
    J --> L["共享限流与群发送锁"]
    K --> L
```

因此，当前优先级准确表达为：排队中的 @/回复 Bot 消息优先于普通消息，但不保证严格优先发送。最终发送仍受模型耗时、全局限流和群发送锁影响。
