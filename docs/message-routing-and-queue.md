# 消息判断与队列链路

本文记录当前已部署版本的消息判断与队列行为。图中描述的是现状，不包含尚未实施的 P0-P3 两阶段调度方案。

## 消息判断链路

知识库初检只准备候选资料，语义规划结果才决定消息进入知识问答、闲聊、Bot 内部信息或身份回复分支。

```mermaid
flowchart TD
    A["QQ群消息"] --> B["硬关系检查：群、@、引用、发送者"]
    B --> C["分段合并并进入持久队列"]
    C --> D["读取近期上下文、追问关系、记忆候选"]
    D --> E["知识库初检"]
    E --> F["语义规划：受话人、意图、参与关系"]
    F --> G{"语义意图"}
    G -->|knowledge| H["检查知识命中强度"]
    G -->|闲聊/调侃/批评等| I["闲聊或被@ fallback"]
    G -->|bot_meta| J["能力复核 + 管理员鉴权"]
    G -->|identity| K["固定身份回复"]
    H -->|强命中| L["知识库回答"]
    H -->|弱命中且明确对 Bot 说| I
    H -->|弱命中且未对 Bot 说| M["不回复"]
    I --> N["生成回复"]
    J --> N
    K --> N
    L --> N
    N --> O["终审、晚消息复核、事实校验"]
    O --> P["限流、发送锁、OneBot 确认、审计"]
```

## 当前队列与软抢占

当前使用两条独立入口处理通道。排队中的普通消息会为 @/回复 Bot 的消息让路；已经开始的普通模型请求不会被强制中断。

```mermaid
flowchart LR
    A["消息进入"] --> B["分段聚合"]
    B --> C{"是否 @ / 回复 Bot"}
    C -->|是| D["优先队列 priority=0"]
    C -->|否| E["普通队列 priority=1"]
    D --> F["优先 Worker"]
    E --> G["普通 Worker"]
    G --> H{"优先队列有消息？"}
    H -->|有| I["普通消息重新入队，等待 50ms"]
    H -->|没有| J["开始规划和生成"]
    F --> K["立即开始规划和生成"]
    J --> L["共享限流与群发送锁"]
    K --> L
```

因此，当前优先级准确表达为：排队中的 @/回复 Bot 消息优先于普通消息，但不保证严格优先发送。最终发送仍受模型耗时、全局限流和群发送锁影响。
